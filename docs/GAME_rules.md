# Party Games — Current Game Rules & Architecture

> Reference document for the "Party Games" real-time multiplayer engine in this repository.
> This file records the game currently implemented in the system and the architecture that should
> be kept improving it.

---

## 1. What "Party Games" currently is

**Party Games** is a mobile-first, real-time multiplayer **party / social-deduction game engine**
built with React 19, TypeScript, Tailwind CSS v4, Express, and Socket.IO.

- All players join from their own phones; there is no shared monitor or TV.
- The server is **authoritative**: it owns the full room state, secret roles, hidden words,
  submitted answers, and the phase state machine.
- Players receive a **masked public** state for the room and a **targeted private** state for
  themselves, so secret roles and hidden words cannot be snooped through dev tools or the network
  inspector.
- A 4-character room code + QR code are used for joining.
- A "next-round" loop lets a host replay a new round with a fresh role assignment.

> **Availability.** **Top 100** and **Mafia** are selectable in the app today. Impostor, Avoid the
> Word, Guess the Link and Reverse Categories are marked `comingSoon` in `shared/data/games.ts`:
> their cards appear with a **Coming Soon** badge, cannot be selected or launched, and the server
> falls back to `DEFAULT_GAME` when a room still points at one of them. Their rules below are kept
> for the engines and test suites, not as a promise that the game is live.

---

## 2. Accepted rules for the system

These are the ground rules the engine currently implements and should continue to honor.

### 2.1 Player and room rules

- Each game validates its own table size: **3–12** for Impostor, **4–16** for Mafia, **3–10** for
  Avoid the Word, **3–8** for Guess the Link, **3–10** for Top 100 and **3–8** for Reverse
  Categories. A room itself holds up to **16** seats, so a Mafia table never runs out of room; the
  game's own minimum blocks Start instead.
- The host creates the room; other players join by a **4-character room code**.
- A room runs in one of two **play modes**: `solo` (default — exactly the original behaviour) or
  `team`. The host picks it from the room settings gear in the lobby, before a round starts.
- Each player is assigned a **color index (0–5)** that loops by join order.
- Session tokens are generated by the server and used to keep a player's identity stable
  across reconnection.
- A player who disconnects can reconnect by a previous name or session token.
- If the host disconnects, a new active non-bot player is promoted to host.

### 2.2 Phase rules

The implemented round phases, in order, are:

1. `lobby` — players join; the host configures bots and launches.
2. `game-select` — the host selects a game (default: Impostor).
3. `reveal` — private role assignment (Impostor role, the Avoid the Word anchor's question, or
   Mafia roles), or public round content (the Reverse Categories items, or the Top 100 question —
   the ranked list itself never leaves the server).
4. `input` — players submit one-word clues (Impostor only).
5. `reveal-answers` — clues are revealed simultaneously (Impostor only), the shuffled link board
   appears (Guess the Link only), the guesses board with its host overrules appears (Top 100 only),
   or the shuffled category board appears (Reverse Categories only).
6. `guess` — everyone privately locks in a guess at the hidden concept at the same time (Guess the
   Link only).
7. `discussion` — timed group discussion (Impostor; the Mafia day phase, with a host skip and a
   ready-to-vote majority).
8. `vote` — secret ballot (Impostor and Reverse Categories, where it crowns the best invented
   category instead of accusing a suspect; Mafia exile votes use it too).
9. `avoid-anchor` → `avoid-turn` (repeats per alive player) → `avoid-reveal` — Avoid the Word's
   private anchor answer, one timed turn at a time, then the public round reveal with the host's
   overrules and Continue.
10. `night` — every living player gets the same private screen: the Mafia pick a victim (and see
    teammates' live picks), the Doctor protects, the Detective investigates, and everyone else
    confirms a harmless decoy (Mafia only).
11. `mafia-morning` — the server narrates the night, privately gives a surviving Detective their
    result, then checks the win condition (Mafia only).
12. `mafia-exile` — the public vote tally and exile outcome, then another win check before the
    loop returns to `night` (Mafia only).
13. `results` — tally reveal, role exposure, per-turn breakdown, recap, and standings.
14. `next-round` — new round (new word, a fresh role deal, a new concept, or a fresh hidden list).

Games with a dedicated engine follow their own chain: Impostor runs
`reveal → input → reveal-answers → discussion → vote → results`, Avoid the Word runs
`reveal → avoid-anchor → avoid-turn (repeats) → avoid-reveal → results` (its Continue either deals
the next round or lands on `results` once the game is decided), Mafia runs
`reveal → night → mafia-morning → discussion → vote → mafia-exile → … → results` (looping back to
`night` after every exile until one faction wins; one full game is one room round), Guess the Link
runs `reveal → input → reveal-answers → guess → results`, Top 100 runs
`reveal → input → reveal-answers → results`, and Reverse Categories runs
`reveal → input → reveal-answers → vote → results` (it reuses the standard ballot instead of
discussion). `day` remains a legacy phase name for older Mafia rooms.

### 2.3 Impostor game rules

Impostor has **two modes**, chosen by the host in the game-select settings panel (public state):
**Word** (default) and **Question**.

- **Host settings (game-select, public):** **mode** (*Word* / *Question*); in word mode a
  **difficulty** — *Easy* (everyday words), *Medium* (less common words) or *Any* (the whole pool)
  — and, when the server has a working AI provider, an optional **custom theme** of up to 40
  characters; in question mode a **tone** (*Clean*, default, or *Spicy*, mild-innuendo questions
  only). Settings are strategy, not secrets: everyone sees them, non-hosts read-only, and they lock
  once a round starts.
- **Word source:** the word is served by the content engine
  (`server/content/wordProvider.ts`) from a 2,059-noun corpus
  (`shared/data/words/commonNouns.json`). Each room has its own **shuffle bag**, so a word cannot
  repeat until that room has seen the whole pool — including across `next-round` loops — and an AI
  top-up (when available) may add validated words to the same bag in the background.
- **Role assignment:** one player is randomly selected as **The Impostor**; the other players are
  **Crew Members**.
- **Secrets:**
  - Crew players see the secret word plus a category hint.
  - The Impostor sees only the category hint, with a message such as "You do NOT know the secret
    word."
- **Clue phase:** every player submits a **single-word clue**. The clue is held privately until
  the reveal phase.
- **Reveal:** all clues (or placeholders for late/non-submissions) are shown to everyone in a
  **randomized order**, not in join order or alphabetical order, to avoid order bias.
- **Discussion:** players cross-examine clues and debate who is bluffing.
- **Vote:** each player casts one secret vote for the player they suspect is the Impostor.
- **Results:**
  - If the Impostor is the **sole** candidate with the highest vote count, they are caught.
  - If the Impostor evades detection (majority voted wrong), the Impostor receives a point.
  - Each correct voter receives a point.
  - Scores are updated and the round ends.

#### 2.3.1 Impostor — Question mode

Everyone privately receives a question. All crew share one question (Q); the impostor receives a
related but different one (Q'). Everyone answers privately, answers are revealed together, and the
existing discussion → vote → results flow then runs unchanged. The impostor's whole job is to read
the answer board, notice their question differed, and blend in anyway.

- **Phase mapping (existing phases and timers):** `reveal` (10s) shows each player **only their own
  question** and never hints that another version exists; `input` (30s) collects the answer;
  `reveal-answers` (15s) shows the board; then the unchanged `discussion` → `vote` → `results`.
- **Answer types** (`answerType` in the pair): `player` — tap a player chip, yourself included;
  `text` — one short answer, at most 40 characters and 4 words, trimmed, whitespace collapsed,
  control characters stripped; `number` — inside the pair's `numberRange`; `choice` — one of the
  pair's shared `choices`.
- **The answer board** is a Fisher-Yates shuffle of name → answer. `player` answers render as that
  player's chip, late answers render as `(No answer)`, and **neither question is shown here**.
- **Discussion and vote** are unchanged. Each player may re-open **their own** question in a
  collapsible card that only they can see.
- **Results** additionally show both questions (crew and impostor) plus a one-line "why it showed"
  note. Scoring is identical to word mode.
- **Pair invariants (hard rules):** both sides always share one `answerType`, the same `choices` and
  the same `numberRange`; the two questions clearly differ in meaning while their answers stay
  plausible side by side, otherwise the impostor is exposed instantly.
- **The `{target}` rule:** when a pair `needsTarget`, the server picks the target from the **crew
  only**. The target receives `crew.selfText`, other crew receive `crew.text` with the target's name
  filled in, and the impostor receives `impostor.text` with that same name filled in.
- **Question source:** `server/content/questionProvider.ts` serves a tone-filtered per-room shuffle
  bag over 160 hand-reviewed pairs (`shared/data/questions/impostorQuestions.json`) and tops it up
  in the background with validated AI pairs (about 20 at a time when fewer than 15 remain).
- **Bots:** `player` picks at random, `number` picks randomly inside the range, `choice` picks at
  random, and `text` uses a small canned list per kind. Bots never call the AI.

### 2.4 Avoid the Word game rules

Avoid the Word is an **elimination game** over several rounds: one anchor answers a question
privately, everyone else answers the same question on their own turn, and any answer that matches
the anchor knocks that player out.

- **Players:** 3-10. Eliminated players stay in the room as **spectators** (public state and
  reveals only).
- **Anchor pick:** at the start of every round the server picks the anchor from the alive players
  with a **rotation bag** — nobody anchors twice until every alive player has, and the same player
  never anchors two rounds in a row while there is a choice.
- **The question:** served by the content engine (`server/content/avoidQuestionProvider.ts`) from
  `shared/data/questions/avoidTheWordQuestions.json` through a per-room shuffle bag, so no question
  repeats until the room has seen the whole eligible pool. Only the **anchor's private state** ever
  carries the question text; the public state only says who is holding it.
- **Answer shapes:** `text` (a broad prompt, max 3 words / 30 characters), `choice` (at least 8
  options), `number` (a range of at least 20 values), `player` (a "who here" pick, only at 5+
  alive). A question is only eligible when its answer space is comfortably bigger than the table:
  `options ≥ alive players + 4`, numeric range ≥ 20 values, `player` questions at 5+ alive.
- **Anchor answer (default 30s):** the anchor answers privately in the question's shape. The answer
  is held server-side and never leaves it until the round reveal; the anchor can never be
  eliminated in their own round.
- **Turns (default 20s each, one at a time):** the same question goes to every other alive player in
  a fresh randomized order each round. On a player's turn only that player gets the input; everyone
  else sees "<name> is answering..." plus a **status strip** for the whole table (waiting / safe /
  matched / skipped / out). The server compares each answer to the anchor's hidden answer the moment
  it arrives:
  - **match** → the player is marked **matched** and the room gets a live "<name> matched the
    anchor's answer!" banner. The announcement never contains the answer text.
  - **no match** → the player is marked **safe**.
  - **timeout / disconnect** → the turn is auto-submitted as `(no answer)` and marked **skipped**
    (counts as safe). **Two consecutive skips eliminate the player as AFK.**
  - A player who has answered never sees anyone else's answer during the round.
- **Round reveal:** after the last turn the question, the anchor's answer and every answer become
  public with matches highlighted, plus a preview of who is about to be eliminated. Until the host
  taps **Continue**, the host can **overrule** any single answer (*count as match* / *not a match*)
  to settle synonyms, near-misses or typos; the final list is what applies.
- **Answer matching** (`server/games/avoidTheWord.match.ts`, unit-tested by `npm run test:avoid`):
  text is normalised (lowercase → NFKD with diacritics stripped → punctuation removed → leading
  article dropped → whitespace collapsed → naive trailing plural folded) and matches when the two
  normalised strings are equal, when one is a stem of the other, or when they are one edit apart
  with both at least 5 characters; `choice` matches the same option, `number` the same value, and
  `player` the same chosen player.
- **Scoring:** the anchor scores **+1 for every player who matched** them (it rewards picking the
  answer the group would say), and every game winner scores **+3**. Nothing else scores, and every
  award goes through `awardPoints()`.
- **End conditions:** the game ends when 1 player is left alive, when everyone but the anchor
  matched (the anchor is the only survivor), or when the **round cap** (10 by default) is reached —
  then all players still alive share the win.
- **Team mode:** a team stays in while it has at least one alive member; anchors rotate across alive
  players from every team; the game ends when one team remains (that team wins) or at the round cap
  (teams with alive members share the win).
- **Placements:** by elimination order — the last player eliminated places highest, and players
  eliminated in the same round tie.
- **Host settings (game-select, public):** anchor answer time (10-60s), turn time (10-60s), round
  cap (3-20) and question **tone** (*Clean* by default, or *Spicy*, which stays mild — cheekier
  everyday questions, never rude ones). Non-hosts see them read-only and they lock once a game
  starts.
- **Bots:** bot anchors and bot turn players answer from the question's own `botAnswers`, options,
  numeric range or the alive players after a short beat. Bots never call the AI.
- **Reconnect:** a reconnecting player gets the question back if their own window is still open
  (with the remaining time from the public timer); a player who drops during their own window is
  treated as a timeout so the round never stalls on a ghost.

### 2.5 Mafia game rules

**Players:** 4–16. One full game — many nights and days until a faction wins — is **one room round**;
Next round deals a completely fresh game. It is phone-only: there is no moderator and no shared
screen, the server is the narrator.

**Roles.**

- **Townsperson** — no ability; wins with Town.
- **Mafia** — knows the other Mafia; each night the Mafia choose one victim; wins with Mafia.
- **Detective** — investigates one player each night and privately learns *Mafia* / *Not Mafia*;
  Town.
- **Doctor** — protects one player each night, may self-protect, may not protect the same player on
  consecutive nights; Town.

**Role deal (server-side, random).**

- `mafiaCount = host override`, or auto `max(1, round(N / 4))`, always clamped to at most
  `floor((N - 1) / 2)` so the Mafia are strictly fewer than half the table.
- **Detective** when `N ≥ 4` and the host setting is on (default on); **Doctor** when `N ≥ 6` and the
  setting is on (default on); everyone else is a Townsperson.
- The role card is hidden behind **press-and-hold to reveal**, so a glance over the shoulder cannot
  leak it. Mafia also see their teammates there. Roles never appear in public state.

**Flow.**

1. `reveal` (about 10s) — private hold-to-reveal role, plus teammates for Mafia.
2. `night` (30s) — every living player sees an **identical** layout, player grid and timer, so a role
   cannot be inferred from timing or layout:
   - Mafia pick a victim (not a Mafia member) and see each other's current picks live. The victim is
     the most-voted Mafia pick; ties break at random; no Mafia vote means nobody is attacked.
   - Doctor picks a protect target under the no-repeat rule. Detective picks an investigate target.
     Townspeople (and any role with nothing to do) pick a harmless decoy — *"Who do you trust the
     most?"* — which does nothing.
   - The phase ends when every living player confirms or the timer expires, plus a random 1–2s beat
     after the last confirmation. Public state shows only the confirmed count.
3. `mafia-morning` (about 8s) — the Mafia target dies unless the Doctor protected them. Narration
   announces the death by name (plus role when `revealRoleOnDeath` is on) or *"Nobody died tonight."*
   It never says whether a save happened. A surviving Detective receives their result now; a
   Detective killed overnight receives nothing. The win condition is checked immediately.
4. `discussion` (120s) — the living argue out loud (the app only runs the timer). A public log of
   past nights and exiles stays visible; the Detective can reopen private notes. The host can skip,
   and it ends early when more than half of the living tap **ready to vote**.
5. `vote` (30s) — every living player secretly votes for one living player or **Skip**; ballots stay
   hidden until the tally. The plurality is exiled, but a tie for first — or Skip being top or
   tied — exiles nobody.
6. `mafia-exile` (about 8s) — the tally (who voted for whom) and the exile, with role when enabled.
   The win condition is checked, then the game loops to `night` if it continues.

**Win conditions**, in order, after the morning resolution and after each exile: Town wins when no
Mafia remain alive; Mafia wins when living Mafia ≥ living non-Mafia.

**Dead players** become spectators: public state only, no living roles, no night actions, no
actions of their own. A living player who disconnects during a timed phase is treated as a
skip/abstain.

**Game over (`results`)** reveals every role and the winning faction, with a recap timeline (each
night's Mafia target, Doctor protection and investigation result; each day's tally and exile), the
points and the leaderboard (team leaderboard first in team mode).

**Scoring** (constants at the top of `server/games/mafia.ts`, all through `awardPoints()`): every
member of the winning faction **+3**, and every surviving member of the winning faction **+1** extra.

**Settings** (`gameSettings.mafia`, host-editable on the game-select card, read-only for others):
`nightSeconds` (30), `discussionSeconds` (120), `voteSeconds` (30), `mafiaCount` (`'auto'` or a
number), `detective` (true), `doctor` (true) and `revealRoleOnDeath` (true). The panel shows the
resulting role breakdown, and Start is disabled with the reason when the deal is illegal for the
current table (for example `mafiaCount > floor((N - 1) / 2)`).

**Bots:** night actions random within each role's rules (Mafia avoid teammates, the Doctor respects
the no-repeat rule, the Detective prefers unchecked players); day votes random among living
non-self players, Mafia never vote a teammate, and a Detective bot votes a known Mafia member.

**Narration:** `shared/data/mafiaNarration.ts` holds 10+ non-graphic lines for each of night falls,
a death, a quiet morning, an exile, a Town win and a Mafia win, drawn from a per-room shuffle bag.

### 2.6 Guess the Link game rules

- **Hint dealing:** the server hides one concept and deals every player a **different** hint angle on
  it (six distinct angles per concept, reused in bigger rooms). Each player sees only their own
  angle, the concept's category, its word count, and their angle number.
- **Responses:** each player privately writes one word or a short phrase from their own angle,
  sanitized to 3 words / 24 characters.
- **Link board:** every response is revealed together in shuffled order; the concept itself stays
  hidden.
- **Guessing:** everyone locks in a guess at the hidden concept at the same time — the room sees who
  has locked in, never what they guessed. The phase closes when everyone has guessed or the timer
  ends.
- **Scoring:** **+1** per correct guess (exact answers, plural-insensitive spellings, shipped
  aliases, and answers clearly containing the concept all count).
- **Results:** the concept, every angle, every guess, the correct guessers, a heuristic "biggest
  giveaway" callout, and the cumulative leaderboard.

### 2.7 Top 100 game rules

- **Hidden list:** the server draws one list — a real ranking of exactly 100 items with a question,
  category, as-of date and source — from `shared/data/top100/*.json` through a per-room shuffle
  bag. **The list never leaves the server**: clients only ever see the question, its category and
  (at results) positions 1-10 and 90-100.
- **No repeats, some variety:** a list cannot repeat until the room has seen every eligible list,
  and consecutive rounds avoid the previous round's category whenever another one is available. The
  host's `region` setting ('global' | 'india' | 'mixed') and an optional category allow-list filter
  the bag, and `TOP100_ONLY_VERIFIED=true` restricts play to source-checked lists.
- **The question (8s):** the question text and its category are public, with the scoring line
  ("name something that is on the Top 100 — the deeper it ranks, the more points").
- **One guess each:** every player privately types one free-text guess (±`(no answer)` if the timer
  runs out and they never submitted). There is **no autocomplete** and no suggestion drawn from the
  list. In team mode exactly one guess per team is locked by that round's captain.
- **Scoring:** a guess that matches position N scores exactly **N points** (position 100 = 100,
  position 1 = 1); a guess that matches nothing scores 0.
- **Matching:** exact matches on normalised names and aliases (lowercased, NFKD accents stripped,
  punctuation removed, a leading `@` and leading articles dropped, whitespace collapsed — plurals
  are *not* folded), then typo tolerance of **≤ 1 edit for guesses of 5+ characters** and
  **≤ 2 for 10+ characters**, accepted only when exactly one item is inside that distance. An
  ambiguous guess counts as no match unless the host overrules it.
- **Duplicates:** `duplicatePolicy` decides whether two or more players/teams on the same item all
  score its position (`allow`, default) or none of them do (`zero`).
- **Host overrules:** on the guesses board the host can force any guess onto a specific position, or
  mark it as not on the list. Points only become final when the host taps Continue.
- **Results:** the guesses grid, then positions **1-10** and **90-100** as two separated blocks
  (a player's own guess is shown in its own row when it sits outside them), then the running
  leaderboard — the team leaderboard first in team mode.
- **Team mode (native):** each team captains by rotation (round-robin through its members), so every
  member captains in turn. Teammates may send up to **five 30-character suggestions** per round that
  reach only their own team's sockets, and a captain who runs out of time falls back to the team's
  newest suggestion. Points go to the **team** via `awardTeamPoints()`, which leaves individual
  scores untouched.
- **Content maintenance:** every guess that matched nothing is counted in
  `data/unmatched-guesses.json` (list id + normalised text + count, with no player identity) so
  aliases can be improved later.


### 2.8 Reverse Categories game rules

- **Items:** the server draws **three items that never share a theme** from a 66-item pool
  (`shared/data/reverseCategoriesItems.ts`) and shows them **publicly to everyone at once**. This
  game hides nothing — no secret role, no hidden word, no private reveal.
- **Categories:** each player privately invents one category name that cleverly links all three
  items, sanitized to 6 words / 48 characters.
- **Category board:** every invented category is revealed together in **Fisher-Yates shuffled
  order**, attributed to its author.
- **Voting:** the standard secret ballot is reused unchanged — a vote targets the **author** of the
  category you liked best, and self-votes are rejected, so nobody can crown their own entry.
- **Scoring:** **+2** to each winning category's author (ties included) and **+1** to every voter who
  backed a winning category. A round where nobody votes awards nothing.
- **Results:** the tally, the winning category spotlight, every category with its vote count, and
  the cumulative leaderboard.

### 2.9 Room team mode

- **Play mode.** `solo` or `team`, host-only, locked once a round starts and re-editable back in
  the lobby. Switching to team creates the teams and deals every current player onto one.
- **Teams.** 2 to 4 teams, each with an **icon, a name and an accent** (four team accents in
  `shared/theme/tokens.ts`, deliberately deeper than the six player identity colours, and never
  the only cue — the icon and name always ship with the colour).
- **Joining.** Any player taps a team to join or switch. Players who join a room that already has
  teams are seated on the smallest team automatically. Membership is keyed by the player's
  **sessionToken**, so reconnecting restores the same team.
- **Host tools.** Team count (2–4), rename a team (trimmed, 20 characters, control characters
  stripped), **Auto-balance** and **Shuffle teams** (both split within one player).
- **Start gate.** In team mode the round cannot start until at least two teams each hold a player
  and the game's minimum player count is met; the reason is shown inline. Team sizes that differ by
  more than one player raise a soft warning, never a block.
- **Scoring.** Individual scores are kept exactly as before **and** every award is also added to the
  scoring player's team total. All of it flows through one function, `awardPoints(room, playerId,
  points, reason?)` in `server/scoring.ts` (re-exported by `roomManager`), which is the only place a
  score changes. Team totals are derived from member scores, so a player who switches teams carries
  their points with them.
- **Results.** Solo shows the individual leaderboard as before. Team mode leads with the **team
  leaderboard** (rank, icon, name, total, members and their contributions) and keeps the individual
  scoreboard underneath. The post-game screen shows final team totals the same way.
- **Game support.** Each game declares `teamSupport` in `shared/data/games.ts`: `aggregate` (plays
  as in solo, points roll up) or `native` (the game itself knows about teams). Game-select cards
  badge this as “Teams: scores combine” or “Team-ready”. Avoid the Word is the first **native**
  game: a team survives while it has an alive member and the game ends when one team remains.
- **Impostor in team mode.** Still exactly **one** impostor per round, chosen from all players, and
  voting stays individual — teammates may vote for each other. Only scoring changes.

### 2.10 Control rules

- The **host** controls phase advancement, game selection, bot injection, and the selected game's
  public settings (Impostor difficulty/theme).
- **Non-host players** can only act within their phase: submit a clue, answer the Avoid the Word
  question on their own turn, cast a vote, or let a timer run out.
- Server-side timers drive most phases; the host can override a timer with a skip action.

## 3. Technical architecture notes for the implemented system

### 3.1 Core pattern

The engine follows a **server-authoritative, Socket.IO-based** architecture:

- Express + Socket.IO on port `3000`.
- In development, Vite middleware is mounted inside Express for instant client hot reload.
- In production, Express serves the compiled SPA from `dist/`.

### 3.2 Public / private state separation

`server/roomManager.ts` is the central state manager. It exposes:

- `getPublicRoomState()` — safe to broadcast to everyone.
- `getPlayerPrivateState(room, playerId)` — only for a single player.
- `transitionToPhase()`, `submitInput()`, `castVote()`, `startPhaseTimer()`,
  `handleDisconnect()`.

### 3.3 Round state machine

- Timer-driven auto-advance is enforced server-side.
- `next-round` returns to `reveal` with a fresh round and triggers role re-assignment.
- `activeRounds` in `server/games/impostor.ts` keeps per-room impostor round data (secret word,
  impostor player id).
- `activeRounds` in `server/games/avoidTheWord.ts` keeps the per-room round data (the question, the
  anchor id, the hidden anchor answer, every submitted answer, the alive set, per-player statuses and
  skip streaks, the turn order, the host overrules, the anchor rotation bag and the elimination
  history). The round's question is written into `player:private-state` for the player whose input is
  open only, and the answers join the public state only once `avoid-reveal` opens.
- `activeRounds` in `server/games/mafia.ts` keeps the per-room Mafia state (the role deal, the living
  set, night picks and confirmations, the Doctor's last protection, investigation findings, both
  ballots, day/night counters, narration bags, the current narration lines and the recap timeline).
  The pure rules live in `server/games/mafia.engine.ts`, so the deal, night resolution, vote tally
  and win check are unit-tested without a socket.
- `activeRounds` in `server/games/guessTheLink.ts` keeps the per-room Guess the Link state (the

## 4. Rules the system should harden

These are recommended rules the existing engine should implement or explicitly document as
future work:

1. **Server-side clue format validation.** The current engine relies on client-side trimming and
   length caps. The server should reject or sanitize non-single-word or prohibited clues.
2. **Accountable room lifecycle.** Rooms are in-memory and are not currently cleaned up after a
   host leaves. Stable room lifecycle, idle cleanup, and graceful shutdown are needed for a real
   hosted service.
3. **Resource and rate limits.** Player count, room lifetime, replay rate, and connection limits
   should be enforced.
4. **Persistent storage.** In-memory rooms are lost on restart. A database-backed room store is
   required for production.
5. **Auth and identity.** Session tokens should be long-lived, rotated, and scoped; plus
   reconnection and guest-identity hygiene should be formalized.
6. **Transport and resilience.** Explicit reconnect strategies, heartbeat/timeout handling, and
   socket.io adapter (for multi-process or multi-instance scaling) should be formalized.
7. **Performance.** LocalStorage sync, registration sweeps, and per-room player lists should be
   profiled for growth.
8. **Observability.** Routing, heartbeats, and critical errors should be logged and monitored.

## 5. Adding a game (standing rules)

Every new game must:

1. **Score through `awardPoints()`** — `server/scoring.ts`, re-exported by `server/roomManager.ts`.
   Never touch `player.score` or `team.score` directly; team totals are derived from member scores,
   and one central function is what keeps solo and team leaderboards consistent.
2. **Take its content from the content engine** (`server/content/`) through a `ContentProvider<T>`,
   so prompts, words and question pairs never repeat inside a room. Add a bundled seed data file,
   validate anything AI-written locally before use, and release the room's bag on cleanup.
3. **Work in both room modes** — `solo` and `team`. Declare `teamSupport` in `shared/data/games.ts`
   and expose per-game settings (never secrets) through the game's own settings sheet.
4. **Keep secrets out of public state** — roles, words, questions, answers before reveal, and Top
   100's ranked list only ever live on the server or travel through `player:private-state`.

**Top 100 already ships native team rules** (one locked guess per team, a rotating captain, a
team-private suggestion channel, and points through `awardTeamPoints()`), which is the reference for
the games still to get them:

- **Guess the Link** — each team submits ONE shared guess via a rotating captain; teams score
  separately.
- **Reverse Categories** — each team submits ONE invented category via its captain; players vote for
  the best category but not their own team's; points go to the winning team.
- **Mafia** — Mafia vs Town stay the factions; room teams only aggregate scores.

## 6. Current state

- The engine is **implemented** as a single-process Node/Express + Socket.IO server with a
  React frontend.
- The core "Impostor" game is **functionally present** and aligns with the classic imposter-word
  social-deduction rules.
- **Avoid the Word**, **Mafia**, **Guess the Link**, **Top 100** and **Reverse Categories** also run
  on dedicated engines (a rotating anchor with a hidden answer, one timed turn per player and live
  match announcements with host-overruled eliminations; hidden roles with a hold-to-reveal deal,
  identical role night screens, doctor/detective secrets, narrated mornings, exile ballots, win
  checks and a full recap; hidden concepts with per-player hint angles and simultaneous guessing;
  hidden 100-item ranked lists with position-exact scoring, host overrules and only the 1-10 /
  90-100 slices revealed; and unrelated item triplets with invented categories scored by the
  standard ballot respectively). **Top 100 and Mafia are selectable**; the rest are Coming Soon.
- **Rooms** now run in **solo** or **team** mode, with host-managed teams, a central
  `awardPoints()` scoring path, and team leaderboards on the results and post-game screens.
- **Per-game settings** live behind a gear on each game-select card (Impostor mode/difficulty/tone/
  theme, Avoid the Word's two timers, round cap and question tone, Mafia's mafia count, three timers
  and role toggles, Guess the Link's custom concept, Top 100's rounds, guess time, duplicate
  policy, region and category filters) and **room settings** (play mode, teams, rounds) behind a
  gear in the lobby — no settings are shared between games any more.
- **Production readiness** is not yet reached: no DB, no rate limiting, no room persistence, no
  persistence of rooms on restart, and no formal hardening pass.
