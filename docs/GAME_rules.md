# Party Games — Current Game Rules & Architecture

> Reference document for the "Party Games" real-time multiplayer engine in this repository.
> This file records the game currently implemented in the system and the architecture that should
> be kept improving it.

---

## 1. What "Party Games" currently is

**Party Games** is a mobile-first, real-time multiplayer **party / social-deduction game engine**
built with React 19, TypeScript, Tailwind CSS v4, Express, and Socket.IO.

- All players join from their own phones; there is no shared monitor or TV.
- The server is **authoritative**: it owns the full room state, secret roles, hidden words,
  submitted answers, and the phase state machine.
- Players receive a **masked public** state for the room and a **targeted private** state for
  themselves, so secret roles and hidden words cannot be snooped through dev tools or the network
  inspector.
- A 4-character room code + QR code are used for joining.
- A "next-round" loop lets a host replay a new round with a fresh role assignment.

## 2. Accepted rules for the system

These are the ground rules the engine currently implements and should continue to honor.

### 2.1 Player and room rules

- A room requires **3–12 players** for the Impostor game, **4–16** for Mafia, **3–10** for Avoid the Word,
  and **3–8** for Guess the Link.
- The host creates the room; other players join by a **4-character room code**.
- Each player is assigned a **color index (0–5)** that loops by join order.
- Session tokens are generated by the server and used to keep a player's identity stable
  across reconnection.
- A player who disconnects can reconnect by a previous name or session token.
- If the host disconnects, a new active non-bot player is promoted to host.

### 2.2 Phase rules

The implemented round phases, in order, are:

1. `lobby` — players join; the host configures bots and launches.
2. `game-select` — the host selects a game (default: Impostor).
3. `reveal` — private role assignment (Impostor role, Avoid the Word cards, or Mafia roles).
4. `input` — players submit one-word clues (Impostor only).
5. `reveal-answers` — clues are revealed simultaneously (Impostor only) or the shuffled link board
   appears (Guess the Link only).
6. `guess` — everyone privately locks in a guess at the hidden concept at the same time (Guess the
   Link only).
7. `discussion` — timed group discussion (Impostor only).
8. `vote` — secret ballot (Impostor only).
9. `atw-describe` — Avoid the Word's live rotation of 45-second describing turns.
10. `night` — Mafia (and the Detective, if present) act privately; townspeople wait (Mafia only).
11. `day` — the overnight elimination is announced before discussion and vote (Mafia only).
12. `results` — tally reveal, role exposure, per-turn breakdown, and standings.
13. `next-round` — new round (new word, fresh taboo cards, a fresh role deal, or a new concept).

Games with a dedicated engine follow their own chain: Impostor runs
`reveal → input → reveal-answers → discussion → vote → results`, Avoid the Word runs
`reveal → atw-describe → results`, Mafia runs
`reveal → night → day → discussion → vote → results` (looping back to `night` after every exile
until one side wins), and Guess the Link runs
`reveal → input → reveal-answers → guess → results`.

### 2.3 Impostor game rules

- **Role assignment:** one player is randomly selected as **The Impostor**; the other players are
  **Crew Members**.
- **Secrets:**
  - Crew players see the secret word plus a category hint.
  - The Impostor sees only the category hint, with a message such as "You do NOT know the secret
    word."
- **Clue phase:** every player submits a **single-word clue**. The clue is held privately until
  the reveal phase.
- **Reveal:** all clues (or placeholders for late/non-submissions) are shown to everyone in a
  **randomized order**, not in join order or alphabetical order, to avoid order bias.
- **Discussion:** players cross-examine clues and debate who is bluffing.
- **Vote:** each player casts one secret vote for the player they suspect is the Impostor.
- **Results:**
  - If the Impostor is the **sole** candidate with the highest vote count, they are caught.
  - If the Impostor evades detection (majority voted wrong), the Impostor receives a point.
  - Each correct voter receives a point.
  - Scores are updated and the round ends.

### 2.4 Avoid the Word game rules

- **Cards:** every player privately receives a target subject and **exactly 3** forbidden
  "taboo" trap words (see `shared/data/avoidTheWordPrompts.ts`).
- **Turn order:** describers rotate one at a time; every player describes once per round and the
  starting describer rotates each round.
- **Describing turn:** the active describer talks their subject through out loud for **45
  seconds** while everyone else listens. Their subject and trap words stay on their own screen.
- **Buzz:** listeners see a **buzz** button instead of the subject. Tapping it flags a suspected
  taboo slip; tapping again withdraws it. A **strict majority** of listening players auto-confirms
  the buzz and ends the turn immediately as a miss.
- **Host override:** the host can confirm a pending buzz early or dismiss all buzzes so the
  describer keeps going.
- **Scoring:** a describing turn that survives its timer is a success and scores **+1**; every
  player on a confirmed buzz also scores **+1**. A buzzed-out turn scores nothing for the
  describer.
- **Results:** the round shows a per-turn success/fail breakdown (subject, trap words, buzz count,
  who buzzed) plus the cumulative leaderboard.

### 2.5 Mafia game rules

- **Roles:** `roughly 1 Mafia per 4 players (minimum 1)`, one **Detective** when the table is large
  enough for the role to matter, and **Townspeople** for everyone else. Each player privately sees
  only their own role.
- **Night phase (30s):** every living Mafia secretly selects a player to eliminate (the last pick
  counts, Mafia cannot target their own), and the Detective secretly selects a player to
  **investigate**, learning privately whether that player is Mafia. Townspeople and eliminated
  players see a "The Town Sleeps…" waiting screen.
- **Day phase:** the overnight elimination — **who**, never who did it — is announced to everyone,
  then the existing `discussion` and `vote` phases run unchanged to exile a suspect.
- **Win condition:** checked after every elimination or exile — Mafia wins when
  `living Mafia ≥ living townspeople`, Town wins when every Mafia is eliminated, otherwise the
  game loops back to night with the survivors.
- **Scoring:** **+1** per surviving Town/Detective on a Town win, **+1** per surviving Mafia on a
  Mafia win; eliminated players score nothing.
- **Results:** final role reveal for every player, the winning side, the night-by-night game log,
  and the cumulative leaderboard.

### 2.6 Guess the Link game rules

- **Hint dealing:** the server hides one concept and deals every player a **different** hint angle on
  it (six distinct angles per concept, reused in bigger rooms). Each player sees only their own
  angle, the concept's category, its word count, and their angle number.
- **Responses:** each player privately writes one word or a short phrase from their own angle,
  sanitized to 3 words / 24 characters.
- **Link board:** every response is revealed together in shuffled order; the concept itself stays
  hidden.
- **Guessing:** everyone locks in a guess at the hidden concept at the same time — the room sees who
  has locked in, never what they guessed. The phase closes when everyone has guessed or the timer
  ends.
- **Scoring:** **+1** per correct guess (exact answers, plural-insensitive spellings, shipped
  aliases, and answers clearly containing the concept all count).
- **Results:** the concept, every angle, every guess, the correct guessers, a heuristic "biggest
  giveaway" callout, and the cumulative leaderboard.

### 2.7 Control rules

- The **host** controls phase advancement, game selection, and bot injection.
- **Non-host players** can only act within their phase: submit a clue, cast a vote, buzz a taboo
  slip, or skip a timer.
- Server-side timers drive most phases; the host can override a timer with a skip action.

## 3. Technical architecture notes for the implemented system

### 3.1 Core pattern

The engine follows a **server-authoritative, Socket.IO-based** architecture:

- Express + Socket.IO on port `3000`.
- In development, Vite middleware is mounted inside Express for instant client hot reload.
- In production, Express serves the compiled SPA from `dist/`.

### 3.2 Public / private state separation

`server/roomManager.ts` is the central state manager. It exposes:

- `getPublicRoomState()` — safe to broadcast to everyone.
- `getPlayerPrivateState(room, playerId)` — only for a single player.
- `transitionToPhase()`, `submitInput()`, `castVote()`, `startPhaseTimer()`,
  `handleDisconnect()`.

### 3.3 Round state machine

- Timer-driven auto-advance is enforced server-side.
- `next-round` returns to `reveal` with a fresh round and triggers role re-assignment.
- `activeRounds` in `server/games/impostor.ts` keeps per-room impostor round data (secret word,
  impostor player id).
- `activeRounds` in `server/games/avoidTheWord.ts` keeps the per-room taboo round data (prompts per
  player, describer rotation, turn results, current buzz set, confirmed flag).
- `activeRounds` in `server/games/mafia.ts` keeps the per-room Mafia state (role assignment, living
  players, night picks, investigation results, elimination history, and scoring).
- `activeRounds` in `server/games/guessTheLink.ts` keeps the per-room Guess the Link state (the
  hidden concept, the dealt angles, responses, guesses, and the concepts already played).

### 3.4 Data and assets

- `data/wordlist.json` — 100 curated, difficulty-stratified thematic nouns.
- `shared/data/impostorWords.ts` — typed word helpers.
- `shared/data/avoidTheWordPrompts.ts` — 40 original subjects, each with exactly 3 trap words.
- `shared/data/games.ts` — the six available game metadata entries.
- `shared/theme/tokens.ts` — player color palette, spacing, radii, typography tokens.
- `client/src/services/sound.ts` — Web Audio notifications and haptic feedback with a mute
  preference.
- `client/src/screens/AtwRevealScreen.tsx`, `AtwDescriberScreen.tsx`, `AtwListenerScreen.tsx`,
  `AtwResultsScreen.tsx` — the Avoid the Word views (reveal, describer, listener, results).
- `server/games/mafia.ts` — the Mafia engine (role deal, night actions, win conditions, scoring).
- `client/src/screens/MafiaRevealScreen.tsx`, `MafiaNightActionScreen.tsx`,
  `MafiaTownSleepsScreen.tsx`, `MafiaMorningScreen.tsx`, `MafiaResultsScreen.tsx` — the Mafia
  views; the day phase reuses `DiscussionPhaseScreen` and `VotePhaseScreen` as-is.
- `shared/data/guessTheLinkPrompts.ts` — 44 original concepts, each with 6 hint angles.
- `server/games/guessTheLink.ts` — the Guess the Link engine (concept hiding, hint dealing,
  response sanitizing, the shuffled board, simultaneous guessing, scoring).
- `client/src/screens/GtlHintRevealScreen.tsx`, `GtlInputScreen.tsx`,
  `GtlResponseRevealScreen.tsx`, `GtlGuessScreen.tsx`, `GtlResultsScreen.tsx` — the Guess the
  Link views.

### 3.5 Client-side responsibilities (must stay read-only for secrets)

- Join / create / reconnect flows.
- Rendering public phase UI.
- Submitting *inputs* (clues, votes) to the server.
- Displaying public lists and public results.
- Consuming private state sent by the server (`player:private-state`).

## 4. Rules the system should harden

These are recommended rules the existing engine should implement or explicitly document as
future work:

1. **Server-side clue format validation.** The current engine relies on client-side trimming and
   length caps. The server should reject or sanitize non-single-word or prohibited clues.
2. **Accountable room lifecycle.** Rooms are in-memory and are not currently cleaned up after a
   host leaves. Stable room lifecycle, idle cleanup, and graceful shutdown are needed for a real
   hosted service.
3. **Resource and rate limits.** Player count, room lifetime, replay rate, and connection limits
   should be enforced.
4. **Persistent storage.** In-memory rooms are lost on restart. A database-backed room store is
   required for production.
5. **Auth and identity.** Session tokens should be long-lived, rotated, and scoped; plus
   reconnection and guest-identity hygiene should be formalized.
6. **Transport and resilience.** Explicit reconnect strategies, heartbeat/timeout handling, and
   socket.io adapter (for multi-process or multi-instance scaling) should be formalized.
7. **Performance.** LocalStorage sync, registration sweeps, and per-room player lists should be
   profiled for growth.
8. **Observability.** Routing, heartbeats, and critical errors should be logged and monitored.

---

## 5. Current state

- The engine is **implemented** as a single-process Node/Express + Socket.IO server with a
  React frontend.
- The core "Impostor" game is **functionally present** and aligns with the classic imposter-word
  social-deduction rules.
- **Avoid the Word**, **Mafia**, and **Guess the Link** also run on dedicated engines (taboo turns
  with buzz confirmation, hidden roles with night/day elimination loops, and hidden concepts with
  per-player hint angles and simultaneous guessing respectively).
- **Production readiness** is not yet reached: no DB, no rate limiting, no room persistence, no
  persistence of rooms on restart, and no formal hardening pass.
