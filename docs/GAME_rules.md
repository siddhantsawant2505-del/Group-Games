# Party Games — Current Game Rules & Architecture

> Reference document for the "Party Games" real-time multiplayer engine in this repository.
> This file records the game currently implemented in the system and the architecture that should
> be kept improving it.

---

## 1. What "Party Games" currently is

**Party Games** is a mobile-first, real-time multiplayer **party / social-deduction game engine**
built with React 19, TypeScript, Tailwind CSS v4, Express, and Socket.IO.

- All players join from their own phones; there is no shared monitor or TV.
- The server is **authoritative**: it owns the full room state, secret roles, hidden words,
  submitted answers, and the phase state machine.
- Players receive a **masked public** state for the room and a **targeted private** state for
  themselves, so secret roles and hidden words cannot be snooped through dev tools or the network
  inspector.
- A 4-character room code + QR code are used for joining.
- A "next-round" loop lets a host replay a new round with a fresh role assignment.

---

## 2. Accepted rules for the system

These are the ground rules the engine currently implements and should continue to honor.

### 2.1 Player and room rules

- A room requires **3–12 players** for the Impostor game, **4–16** for Mafia, **3–10** for Avoid the Word,
  **3–8** for Guess the Link, **3–10** for Top 100, and **3–8** for Reverse Categories.
- The host creates the room; other players join by a **4-character room code**.
- Each player is assigned a **color index (0–5)** that loops by join order.
- Session tokens are generated by the server and used to keep a player's identity stable
  across reconnection.
- A player who disconnects can reconnect by a previous name or session token.
- If the host disconnects, a new active non-bot player is promoted to host.

### 2.2 Phase rules

The implemented round phases, in order, are:

1. `lobby` — players join; the host configures bots and launches.
2. `game-select` — the host selects a game (default: Impostor).
3. `reveal` — private role assignment (Impostor role, Avoid the Word cards, or Mafia roles).
4. `input` — players submit one-word clues (Impostor only).
5. `reveal-answers` — clues are revealed simultaneously (Impostor only), the shuffled link board
   appears (Guess the Link only), the shuffled example board appears (Top 100 only), or the
   shuffled category board appears (Reverse Categories only).
6. `guess` — everyone privately locks in a guess at the hidden concept at the same time (Guess the
   Link only).
7. `rank` — the host drags the Top 100 examples into ascending numeric order while everyone else
   watches the order update live (Top 100 only).
8. `discussion` — timed group discussion (Impostor only).
9. `vote` — secret ballot (Impostor and Reverse Categories, where it crowns the best invented
   category instead of accusing a suspect; Mafia exile votes use it too).
10. `atw-describe` — Avoid the Word's live rotation of 45-second describing turns.
11. `night` — Mafia (and the Detective, if present) act privately; townspeople wait (Mafia only).
12. `day` — the overnight elimination is announced before discussion and vote (Mafia only).
13. `results` — tally reveal, role exposure, per-turn breakdown, and standings.
14. `next-round` — new round (new word, fresh taboo cards, a fresh role deal, a new concept, or a
   fresh spectrum with new secret numbers).

Games with a dedicated engine follow their own chain: Impostor runs
`reveal → input → reveal-answers → discussion → vote → results`, Avoid the Word runs
`reveal → atw-describe → results`, Mafia runs
`reveal → night → day → discussion → vote → results` (looping back to `night` after every exile
until one side wins), Guess the Link runs
`reveal → input → reveal-answers → guess → results`, Top 100 runs
`reveal → input → reveal-answers → rank → results`, and Reverse Categories runs
`reveal → input → reveal-answers → vote → results` (it reuses the standard ballot instead of
discussion).

### 2.3 Impostor game rules

Impostor has **two modes**, chosen by the host in the game-select settings panel (public state):
**Word** (default) and **Question**.

- **Host settings (game-select, public):** **mode** (*Word* / *Question*); in word mode a
  **difficulty** — *Easy* (everyday words), *Medium* (less common words) or *Any* (the whole pool)
  — and, when the server has a working AI provider, an optional **custom theme** of up to 40
  characters; in question mode a **tone** (*Clean*, default, or *Spicy*, mild-innuendo questions
  only). Settings are strategy, not secrets: everyone sees them, non-hosts read-only, and they lock
  once a round starts.
- **Word source:** the word is served by the content engine
  (`server/content/wordProvider.ts`) from a 2,059-noun corpus
  (`shared/data/words/commonNouns.json`). Each room has its own **shuffle bag**, so a word cannot
  repeat until that room has seen the whole pool — including across `next-round` loops — and an AI
  top-up (when available) may add validated words to the same bag in the background.
- **Role assignment:** one player is randomly selected as **The Impostor**; the other players are
  **Crew Members**.
- **Secrets:**
  - Crew players see the secret word plus a category hint.
  - The Impostor sees only the category hint, with a message such as "You do NOT know the secret
    word."
- **Clue phase:** every player submits a **single-word clue**. The clue is held privately until
  the reveal phase.
- **Reveal:** all clues (or placeholders for late/non-submissions) are shown to everyone in a
  **randomized order**, not in join order or alphabetical order, to avoid order bias.
- **Discussion:** players cross-examine clues and debate who is bluffing.
- **Vote:** each player casts one secret vote for the player they suspect is the Impostor.
- **Results:**
  - If the Impostor is the **sole** candidate with the highest vote count, they are caught.
  - If the Impostor evades detection (majority voted wrong), the Impostor receives a point.
  - Each correct voter receives a point.
  - Scores are updated and the round ends.

#### 2.3.1 Impostor — Question mode

Everyone privately receives a question. All crew share one question (Q); the impostor receives a
related but different one (Q'). Everyone answers privately, answers are revealed together, and the
existing discussion → vote → results flow then runs unchanged. The impostor's whole job is to read
the answer board, notice their question differed, and blend in anyway.

- **Phase mapping (existing phases and timers):** `reveal` (10s) shows each player **only their own
  question** and never hints that another version exists; `input` (30s) collects the answer;
  `reveal-answers` (15s) shows the board; then the unchanged `discussion` → `vote` → `results`.
- **Answer types** (`answerType` in the pair): `player` — tap a player chip, yourself included;
  `text` — one short answer, at most 40 characters and 4 words, trimmed, whitespace collapsed,
  control characters stripped; `number` — inside the pair's `numberRange`; `choice` — one of the
  pair's shared `choices`.
- **The answer board** is a Fisher-Yates shuffle of name → answer. `player` answers render as that
  player's chip, late answers render as `(No answer)`, and **neither question is shown here**.
- **Discussion and vote** are unchanged. Each player may re-open **their own** question in a
  collapsible card that only they can see.
- **Results** additionally show both questions (crew and impostor) plus a one-line "why it showed"
  note. Scoring is identical to word mode.
- **Pair invariants (hard rules):** both sides always share one `answerType`, the same `choices` and
  the same `numberRange`; the two questions clearly differ in meaning while their answers stay
  plausible side by side, otherwise the impostor is exposed instantly.
- **The `{target}` rule:** when a pair `needsTarget`, the server picks the target from the **crew
  only**. The target receives `crew.selfText`, other crew receive `crew.text` with the target's name
  filled in, and the impostor receives `impostor.text` with that same name filled in.
- **Question source:** `server/content/questionProvider.ts` serves a tone-filtered per-room shuffle
  bag over 160 hand-reviewed pairs (`shared/data/questions/impostorQuestions.json`) and tops it up
  in the background with validated AI pairs (about 20 at a time when fewer than 15 remain).
- **Bots:** `player` picks at random, `number` picks randomly inside the range, `choice` picks at
  random, and `text` uses a small canned list per kind. Bots never call the AI.

### 2.4 Avoid the Word game rules

- **Cards:** every player privately receives a target subject and **exactly 3** forbidden
  "taboo" trap words (see `shared/data/avoidTheWordPrompts.ts`).
- **Turn order:** describers rotate one at a time; every player describes once per round and the
  starting describer rotates each round.
- **Describing turn:** the active describer talks their subject through out loud for **45
  seconds** while everyone else listens. Their subject and trap words stay on their own screen.
- **Buzz:** listeners see a **buzz** button instead of the subject. Tapping it flags a suspected
  taboo slip; tapping again withdraws it. A **strict majority** of listening players auto-confirms
  the buzz and ends the turn immediately as a miss.
- **Host override:** the host can confirm a pending buzz early or dismiss all buzzes so the
  describer keeps going.
- **Scoring:** a describing turn that survives its timer is a success and scores **+1**; every
  player on a confirmed buzz also scores **+1**. A buzzed-out turn scores nothing for the
  describer.
- **Results:** the round shows a per-turn success/fail breakdown (subject, trap words, buzz count,
  who buzzed) plus the cumulative leaderboard.

### 2.5 Mafia game rules

- **Roles:** `roughly 1 Mafia per 4 players (minimum 1)`, one **Detective** when the table is large
  enough for the role to matter, and **Townspeople** for everyone else. Each player privately sees
  only their own role.
- **Night phase (30s):** every living Mafia secretly selects a player to eliminate (the last pick
  counts, Mafia cannot target their own), and the Detective secretly selects a player to
  **investigate**, learning privately whether that player is Mafia. Townspeople and eliminated
  players see a "The Town Sleeps…" waiting screen.
- **Day phase:** the overnight elimination — **who**, never who did it — is announced to everyone,
  then the existing `discussion` and `vote` phases run unchanged to exile a suspect.
- **Win condition:** checked after every elimination or exile — Mafia wins when
  `living Mafia ≥ living townspeople`, Town wins when every Mafia is eliminated, otherwise the
  game loops back to night with the survivors.
- **Scoring:** **+1** per surviving Town/Detective on a Town win, **+1** per surviving Mafia on a
  Mafia win; eliminated players score nothing.
- **Results:** final role reveal for every player, the winning side, the night-by-night game log,
  and the cumulative leaderboard.

### 2.6 Guess the Link game rules

- **Hint dealing:** the server hides one concept and deals every player a **different** hint angle on
  it (six distinct angles per concept, reused in bigger rooms). Each player sees only their own
  angle, the concept's category, its word count, and their angle number.
- **Responses:** each player privately writes one word or a short phrase from their own angle,
  sanitized to 3 words / 24 characters.
- **Link board:** every response is revealed together in shuffled order; the concept itself stays
  hidden.
- **Guessing:** everyone locks in a guess at the hidden concept at the same time — the room sees who
  has locked in, never what they guessed. The phase closes when everyone has guessed or the timer
  ends.
- **Scoring:** **+1** per correct guess (exact answers, plural-insensitive spellings, shipped
  aliases, and answers clearly containing the concept all count).
- **Results:** the concept, every angle, every guess, the correct guessers, a heuristic "biggest
  giveaway" callout, and the cumulative leaderboard.

### 2.7 Top 100 game rules

- **Spectrum:** the server picks one 1-to-100 spectrum (e.g. "1 = spotless, 100 = certified
  biohazard") from `shared/data/top100Prompts.ts` and shows it to everyone.
- **Secret numbers:** every player privately receives a **unique** number from 1 to 100 — numbers are
  never repeated within a round and nobody sees anyone else's number.
- **Examples:** each player privately writes one short example/scenario they believe sits at their
  own number, sanitized to 9 words / 72 characters.
- **Example board:** every written example appears together in shuffled order with the secret
  numbers still hidden.
- **Ranking (host-authoritative v1):** the host drags the examples into what they believe is
  ascending numeric order; the order broadcasts live and everyone else watches read-only. The
  ranking phase closes when the host locks the order in or the timer ends.
- **Scoring:** the truth is revealed next to every example and the ordering is scored by
  **correctly-placed adjacent pairs** — each neighbouring pair put in the right relative order
  scores **+2**, and a flawless order adds a **+3** bonus. Because the ordering is collaborative,
  the accuracy score is shared by the whole table.
- **Results:** the spectrum with every true number plotted, the group's final order with each
  example's real number and its true position, the pair accuracy, and the cumulative leaderboard.

### 2.8 Reverse Categories game rules

- **Items:** the server draws **three items that never share a theme** from a 66-item pool
  (`shared/data/reverseCategoriesItems.ts`) and shows them **publicly to everyone at once**. This
  game hides nothing — no secret role, no hidden word, no private reveal.
- **Categories:** each player privately invents one category name that cleverly links all three
  items, sanitized to 6 words / 48 characters.
- **Category board:** every invented category is revealed together in **Fisher-Yates shuffled
  order**, attributed to its author.
- **Voting:** the standard secret ballot is reused unchanged — a vote targets the **author** of the
  category you liked best, and self-votes are rejected, so nobody can crown their own entry.
- **Scoring:** **+2** to each winning category's author (ties included) and **+1** to every voter who
  backed a winning category. A round where nobody votes awards nothing.
- **Results:** the tally, the winning category spotlight, every category with its vote count, and
  the cumulative leaderboard.

### 2.9 Control rules

- The **host** controls phase advancement, game selection, bot injection, and the selected game's
  public settings (Impostor difficulty/theme).
- **Non-host players** can only act within their phase: submit a clue, cast a vote, buzz a taboo
  slip, or skip a timer.
- Server-side timers drive most phases; the host can override a timer with a skip action.

## 3. Technical architecture notes for the implemented system

### 3.1 Core pattern

The engine follows a **server-authoritative, Socket.IO-based** architecture:

- Express + Socket.IO on port `3000`.
- In development, Vite middleware is mounted inside Express for instant client hot reload.
- In production, Express serves the compiled SPA from `dist/`.

### 3.2 Public / private state separation

`server/roomManager.ts` is the central state manager. It exposes:

- `getPublicRoomState()` — safe to broadcast to everyone.
- `getPlayerPrivateState(room, playerId)` — only for a single player.
- `transitionToPhase()`, `submitInput()`, `castVote()`, `startPhaseTimer()`,
  `handleDisconnect()`.

### 3.3 Round state machine

- Timer-driven auto-advance is enforced server-side.
- `next-round` returns to `reveal` with a fresh round and triggers role re-assignment.
- `activeRounds` in `server/games/impostor.ts` keeps per-room impostor round data (secret word,
  impostor player id).
- `activeRounds` in `server/games/avoidTheWord.ts` keeps the per-room taboo round data (prompts per
  player, describer rotation, turn results, current buzz set, confirmed flag).
- `activeRounds` in `server/games/mafia.ts` keeps the per-room Mafia state (role assignment, living
  players, night picks, investigation results, elimination history, and scoring).
- `activeRounds` in `server/games/guessTheLink.ts` keeps the per-room Guess the Link state (the
  hidden concept, the dealt angles, responses, guesses, and the concepts already played).
- `activeRounds` in `server/games/top100.ts` keeps the per-room Top 100 state (the spectrum, the
  unique secret numbers, the written examples, the live ordering, and the spectra already played).
- `activeRounds` in `server/games/reverseCategories.ts` keeps the per-room Reverse Categories state
  (the item triplet, the invented categories, and the items already used in that room).
- Per-room content bags live in `server/content/` (never in public room state) and are released by
  `releaseRoomContent(roomId)` when a room resets to the lobby or is swept after two hours with no
  connected player.
- The Impostor reveal calls the content provider, so that one phase finishes asynchronously; every
  other phase stays synchronous.

### 3.4 Data and assets

- `server/content/types.ts` — the `ContentProvider<T>` contract, the shared difficulty setting and
  the theme/word sanitizers.
- `server/content/contentBag.ts` — the per-room shuffle bag (served set, reshuffle guard, AI merges).
- `server/content/aiClient.ts` — the server-side Gemini wrapper (timeout, retry, JSON, rate limit,
  one-time unavailability report).
- `server/content/wordProvider.ts` — words: bundled corpus bag, background AI top-up, local
  validation, prefetch at the discussion phase. Records its data provenance and licences (the
  commonness list is MIT-licensed FrequencyWords data).
- `server/content/questionProvider.ts` — question pairs: tone-filtered bag, background AI top-up,
  and `validateQuestionPair()`, which rejects a pair unless the answer type matches, `choices` and
  `numberRange` match, both texts are 10-120 characters, the two texts are not a reworded copy
  (normalized similarity below 0.8), `{target}` appears on both sides or neither, the tone fits,
  nothing hits the blocklist, and the pair is not already in the room's history.
- `shared/data/questions/impostorQuestions.json` — 160 original question pairs across the six kinds
  (`most-likely`, `about-player`, `preference`, `hypothetical`, `numeric`, `choice`) and all four
  answer types, 34 of them needing `{target}`; 50 are `spicy` tone and only play when the host
  opts in.
- `server/games/impostorQuestionMode.ts` — question-mode dealing (crew question, impostor
  question, target selection), answer sanitizing, the shuffled board, and the results payload.
- `client/src/components/GameSettingsPanel.tsx` — the public post-selection settings panel

- `client/src/screens/ImpostorQuestionRevealScreen.tsx`, `ImpostorAnswerScreen.tsx`,
  `ImpostorAnswersGridScreen.tsx` — the question-mode views (private question, the four answer

- `server/content/index.ts` — `releaseRoomContent(roomId)`, called on lobby resets and idle-room sweeps.
- `shared/data/words/commonNouns.json` — the 2,059-word corpus (27 categories, difficulty tiers 1-3).
- `data/common-words-frequency.txt` — the 10,000 most common English words, used only as the
  "is this word common?" filter for AI output.
- `data/blocklist.txt` — the moderation list applied to AI-generated content.
- `shared/data/avoidTheWordPrompts.ts` — 40 original subjects, each with exactly 3 trap words.
- `shared/data/games.ts` — the six available game metadata entries.
- `shared/theme/tokens.ts` — player color palette, spacing, radii, typography tokens.
- `client/src/services/sound.ts` — Web Audio notifications and haptic feedback with a mute
  preference.
- `client/src/screens/AtwRevealScreen.tsx`, `AtwDescriberScreen.tsx`, `AtwListenerScreen.tsx`,
  `AtwResultsScreen.tsx` — the Avoid the Word views (reveal, describer, listener, results).
- `server/games/mafia.ts` — the Mafia engine (role deal, night actions, win conditions, scoring).
- `client/src/screens/MafiaRevealScreen.tsx`, `MafiaNightActionScreen.tsx`,
  `MafiaTownSleepsScreen.tsx`, `MafiaMorningScreen.tsx`, `MafiaResultsScreen.tsx` — the Mafia
  views; the day phase reuses `DiscussionPhaseScreen` and `VotePhaseScreen` as-is.
- `shared/data/guessTheLinkPrompts.ts` — 44 original concepts, each with 6 hint angles.
- `server/games/guessTheLink.ts` — the Guess the Link engine (concept hiding, hint dealing,
  response sanitizing, the shuffled board, simultaneous guessing, scoring).
- `client/src/screens/GtlHintRevealScreen.tsx`, `GtlInputScreen.tsx`,
  `GtlResponseRevealScreen.tsx`, `GtlGuessScreen.tsx`, `GtlResultsScreen.tsx` — the Guess the

- `shared/data/top100Prompts.ts` — 22 original 1-to-100 spectra with sample examples for bots.

  sanitizing, the shuffled board, host ordering validation, and pair-accuracy scoring).
- `client/src/components/SpectrumBar.tsx` — the shared 1-to-100 spectrum strip.
- `client/src/screens/Top100RevealScreen.tsx`, `Top100InputScreen.tsx`, `Top100BoardScreen.tsx`,
  `Top100RankScreen.tsx`, `Top100ResultsScreen.tsx` — the Top 100 views (private number, example
  input, the example board, the host drag-to-rank screen, and results).
- `shared/data/reverseCategoriesItems.ts` — 66 original items across 22 themes, with the
  unrelated-triplet randomizer.
- `server/games/reverseCategories.ts` — the Reverse Categories engine (triplet picking, category

- `client/src/screens/RevCatItemsScreen.tsx`, `RevCatInputScreen.tsx`,
  `RevCatResultsScreen.tsx` — the Reverse Categories views; the category board and the best-category
  ballot reuse `RevealAnswersScreen` and `VotePhaseScreen` through their optional copy overrides.

### 3.5 Client-side responsibilities (must stay read-only for secrets)

- Join / create / reconnect flows.
- Rendering public phase UI.
- Submitting *inputs* (clues, votes) to the server.
- Displaying public lists and public results.
- Consuming private state sent by the server (`player:private-state`).

## 4. Rules the system should harden

These are recommended rules the existing engine should implement or explicitly document as
future work:

1. **Server-side clue format validation.** The current engine relies on client-side trimming and
   length caps. The server should reject or sanitize non-single-word or prohibited clues.
2. **Accountable room lifecycle.** Rooms are in-memory and are not currently cleaned up after a
   host leaves. Stable room lifecycle, idle cleanup, and graceful shutdown are needed for a real
   hosted service.
3. **Resource and rate limits.** Player count, room lifetime, replay rate, and connection limits
   should be enforced.
4. **Persistent storage.** In-memory rooms are lost on restart. A database-backed room store is
   required for production.
5. **Auth and identity.** Session tokens should be long-lived, rotated, and scoped; plus
   reconnection and guest-identity hygiene should be formalized.
6. **Transport and resilience.** Explicit reconnect strategies, heartbeat/timeout handling, and
   socket.io adapter (for multi-process or multi-instance scaling) should be formalized.
7. **Performance.** LocalStorage sync, registration sweeps, and per-room player lists should be
   profiled for growth.
8. **Observability.** Routing, heartbeats, and critical errors should be logged and monitored.

## 5. Current state

- The engine is **implemented** as a single-process Node/Express + Socket.IO server with a
  React frontend.
- The core "Impostor" game is **functionally present** and aligns with the classic imposter-word
  social-deduction rules.
- **Avoid the Word**, **Mafia**, **Guess the Link**, **Top 100**, and **Reverse Categories** also run
  on dedicated engines (taboo turns with buzz confirmation, hidden roles with night/day elimination
  loops, hidden concepts with per-player hint angles and simultaneous guessing, 1-to-100 spectra
  with unique secret numbers and a host-authoritative ranking phase, and unrelated item triplets
  with invented categories scored by the standard ballot respectively).
- **Production readiness** is not yet reached: no DB, no rate limiting, no room persistence, no
  persistence of rooms on restart, and no formal hardening pass.
